# 模块与个性化报告契约

运行契约由模板中的 report-contract.json 描述。confirmed 只表示规格有依据，不表示图片已生成或通过。

## 类别、领口与风格组

服装类别由用户当前选择、排除项和目标场景决定，优先于照片衣着线索；照片最多用于提出可改选建议，不能用于判断身份。选定男装、女装或中性后，所有穿搭沿用该类别。

report-05 使用用户指定风格组列表与每组套数。每组记录 group_id、style_label、count、look_ids、page_file 和 style_notes；look_ids 个数等于 count。总套数由各组 count 求和。组间差异来自衣服、层次、轮廓与场景，不可只换背景或颜色。

每套造型按 personalized-outfits.md 记录可见或用户提供的依据、设计选择、预期视觉效果、备选方案与试穿点。运行副本的 `outfit_plan.groups[*].look_decisions` 应与同组 `look_ids` 一一对应。证据不足的建议可保留为试穿假设，但不能称“照片证明适合”。这项文字设计在图像生成前完成；图像 QA 再检查实际服装是否落实设计。

若总数与逐组数量不一致，默认问一次。若当前授权要求边等待边继续，则按明确的逐组数量执行，并记录冲突、采用口径和是否有答复。否则不自行猜数。

## 状态

- confirmed：规格已有依据。
- pass：实际图片存在且必检可观察项逐项通过；不是身份认证。
- needs_revision：可见明确偏差。
- not_tested：无实图或无法比较，记录原因。
- blocked：工具、来源素材或功能不可用，不能完成。

## 人像与领口

每个个人化输出须有本任务可读的本人照片。原照应作为人物主要锚点；旧生成图不可作为唯一来源。保持脸部关系、眼镜、可见标记、自然肤质和可见体态。穿搭图可改变衣服、自然动作和场景，不得借机拉宽或重塑人物。

稳定领口 ID 在04、05、06间保持对应。具体搭配只选适用领口；叠穿时说明验收的层。示意、人像实穿和标签必须一致。

## report-05 和 report-06

每个 report-05 风格组按指定数量制作；QA 对每个 look_id 分开记录身份、眼镜、肤质、可见身形、服装层次、领口、动作和风格区分。只有所有套数实存且各项通过，组页才通过。

report-06 总览展示8行、5视觉列、24格。按最终尺寸验收；看不清时保留总览作导航并增加覆盖全行详情，逐格检查。不得用总览小格代替无法完成的核验。
