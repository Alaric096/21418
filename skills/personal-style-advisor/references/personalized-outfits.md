# 从本人照片到个性化穿搭

用于 report-05 或用户要求多套穿搭时。目的不是把人分入固定“脸型/身材/气质”标签，而是让每套搭配都能追溯到可见事实、用户目标与实际使用场景。

## 一、建立可用依据

把依据分成四类，逐项注明来源与把握度：

1. **用户选择**：服装类别、风格组、场景、预算、着装限制、想强调或弱化的部位、是否戴眼镜、喜欢的松紧与露肤度。用户明确选择优先。
2. **照片可见**：发型和发量的视觉表现、眼镜与饰品、可见肩颈和服装轮廓、当前搭配的比例关系、不同颜色在本次光线下的相对表现。记录照片编号和观察范围；勿把滤镜或广角自拍造成的变化当作本人特征。
3. **部分可见**：例如仅看见上半身，只能讨论上衣和已显示的轮廓；可对裤鞋提出试穿方案，但不得声称已测得腿长、腰线或真实尺码。
4. **未知**：身高、精确身材比例、色彩季型、肤质诊断、职业、性格等照片无法确认的内容。未知不作为个性化理由。

“五官”只用于可见造型关系，例如眼镜存在感、发型是否遮住眉眼、领口开合与面部/颈肩画面的平衡。不要把脸部特征转化成性格、价值或性别身份判断。“气质”优先采用用户自述；若只凭照片，可说“这张照片呈现的视觉印象”，注明受姿态、衣着和光线影响，不把印象当成永久属性。

## 二、形成穿搭决策

先写 3—5 条对本次任务有用的决策线索，每条格式为：

`依据（照片/用户选择） → 本次造型目标 → 可调整杠杆 → 限制/试穿验证`

可调整杠杆包括上衣长度和松量、肩线与领口、外套结构、下装廓形、色彩对比、材质视觉重量、层次、配饰和动作。只改变造型，不“修正”本人身体。推荐中同时写一项可替换方案；对颜色和裤鞋等不确定项，用“先试 A 与 B，再在自然光/实际穿着中比较”。

例：照片显示当前上衣较贴身、裤型较宽；用户希望韩系杂志感。可试常规长度的轻结构外套维持上半身利落感，配宽直筒裤；外套肩线、裤腰和鞋履效果需实际试穿确认。这个例子说明推理格式，不是所有人的默认搭配。

## 三、分组与逐套设计

用户指定风格组和数量后才建立组。每组至少定义单品、层次、轮廓和场景的共同语言；每套再选不同的主杠杆或场景，避免“同一套换颜色”。如果用户列出韩系、日系、美式街头、慵懒休闲、偏商务各四套，则是五组共二十套；口头总数与分项不一致时按 report-contract.md 处理。

每个 look_id 必须有：

- 可执行单品清单：上衣、下装、鞋/配饰、需要的外层；注明未在照片中看见的部分是搭配模拟。
- 已选领口 ID；叠穿时指明哪一层展示领口。
- 一项主要个性化依据、对应选择和预期视觉效果；不要复制同一句理由到二十套。
- 场景和姿态；姿态变化不用于制造虚假的身材比例。
- 一项现实试穿检查：肩线、衣长、腰位、下摆、活动度、色彩自然光效果等，按本套风险选择。
- 备选单品或颜色，便于用户按衣柜、预算和舒适度调整。

照片证据不足时仍可完成风格方案，但将个性化理由改成“基于用户目标的试穿假设”，不宣称已从照片证明适合。每个风格组的四套可覆盖低门槛日常、造型感、季节/层次变化和特定场景，但用户要求优先。

## 四、生成和验收

先冻结每套的文字方案、领口 ID 与允许变化，再制作图片。所有图沿用原始本人照片作为人物锚点，按 identity-and-pose.md 检查。生成结果必须和方案一致；若模型把人体肩宽、腰线、腿长、脸部关系或眼镜改掉，不能用“显瘦/显高”当作优点，应修订或标未通过。

QA 除原有身份、数量、风格、动作和领口检查外，还逐套核对：理由是否有真实来源、衣服是否实现该理由、是否把未知当事实、试穿点是否明确。图片通过只代表视觉模拟可读且与方案一致，不证明现实尺码、材质、颜色效果或“最适合”。
