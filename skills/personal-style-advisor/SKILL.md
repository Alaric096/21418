# Personal Style Advisor v5

根据用户目标和本人照片制作实用的发型与穿搭建议。参考图只提供版式和内容线索，不能替代本人照片。用户当前选择、排除项和目标场景优先于照片中的衣着线索；服装目录选择不能用来推断身份。

## 运行路由

- 用户只要发型、上衣搭配或领口适配时，分别读取 [发型提示词](prompts/hair-guide.md)、[上衣造型提示词](prompts/tops-styling.md) 或 [领口与发型提示词](prompts/neckline-hair.md)，不要求先完成完整报告。
- 用户要求全部或部分报告时，读取 [模块与报告契约](references/report-contract.md) 和运行副本 templates/report-contract.json，按 report_id 路由。
- report-05 的风格组与套数由用户选择。每组记录名称、数量、look ID、搭配差异、动作和输出页；不得把固定四套组当作所有任务的限制。
- report-05 在分组前读取 [个性化穿搭决策](references/personalized-outfits.md)：先从照片中提取有把握的可见线索、用户偏好和场景，再逐套决定版型、领口、颜色、层次与动作。每套都要有自己的依据与试穿待验证项；不能把同一组固定搭配套给所有人。
- 没有可读本人照片时可给通用文字，但不得声称已分析本人或生成个人试穿效果。

## 服装类别与领口

优先采用本轮明确选择、排除项和目标场景。照片线索只能用于提出可改选建议；不得将衣着当作性别身份判断。类别会改变版型且尚未明确时，只问一次男装、女装或中性，并继续能独立完成的工作。

按选定类别读取稳定领口目录，写入运行副本。已选领口 ID 顺序在04、05、06中保持一致。具体穿搭可选适配领口，但示意、标签和实穿必须一致；叠穿时说明所验收的领口层。

## report-05 风格组与套数

按用户指定的组名和数量执行。每套使用唯一 look ID，记录上衣、下装、外搭层次、颜色、领口 ID、场景和动作。总套数是各组数量之和。若口头总数与分组之和冲突，默认简短确认一次；若当前授权要求无需等待而继续，则按明确列出的组数量执行并记录冲突与口径，不得默默删组或改数。

每套还要记录“依据 → 选择 → 预期视觉效果 → 限制/试穿点”。依据可来自本人照片中的可见轮廓、发型、眼镜、肤色在当次光线下的表现，以及用户表达的偏好；不可凭照片断定身高、精确身材比例、肤色季型或性格。不同风格组使用同一人的观察记录，但每组保留自己的风格语法。用户没选风格组时才提供可改选建议，不自动输出五组二十套。

风格组之间须由单品、层次、轮廓和场景共同体现差异，不能只换背景或颜色。四套一页时至少三种自然且可见的动作。姿势不得改变脸、肤质或身体宽度；宽松服装不能把人物身体拉宽。服装遵循用户所选男装、女装或中性类别。

## 制作与验收

制作图像前读取 [照片分析提示词](prompts/analyze.md)、[视觉与隐私边界](references/visual-safety.md)、[图像工作流程](references/image-workflow.md) 和 [人物参考与姿态规则](references/identity-and-pose.md)。使用当前会话的可用图像工具；本地原图作为参考前先打开检查。生成真人造型图应引用当前任务可读的原始照片，记录每张图的职责及允许变化项。旧生成图不得作为唯一人物锚点。

按 [逐页复核提示词](prompts/review-report.md) 检查实际图片，在运行副本 templates/qa.md 中逐页逐格记录人物、服装、领口 ID、动作、文字和版式。图片缺失或不可读时标 blocked 或 not_tested，不得把计划或总览误报为通过。pass 仅表示可观察范围内未见明显偏差，不是身份认证。

report-06 默认展示8个稳定领口、8行×5视觉列×24个人像。按最终尺寸核查；小格看不清时保留总览作导航并加做覆盖全部行的详情，逐格检查详情。

每次运行将模板复制到独立结果目录，编辑运行副本，不改模板。只有实际存在、可读且完成复核的图片才计为成品。
